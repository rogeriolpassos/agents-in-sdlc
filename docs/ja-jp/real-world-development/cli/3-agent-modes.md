最初にプロジェクトへ小さな機能を追加しました。大きな変更には、より確実なプロセスが必要です。コマンドライン インターフェイス (CLI) である GitHub Copilot CLI は組織の既存の開発フローに沿って作業できるため、適切なものを適切な方法で構築できます。このレッスンから、エージェントを使った一般的な開発プロセスに沿って作業します。Issue から機能を作り、コードと動作を確認し、最終的にプロジェクトへマージします。

> [!NOTE]
> 機能開発の間は、同じ会話とブランチを使います。通常はファイルの種類ごとに異なるブランチやプルリクエスト (PR) を使いますが、ここでは主な概念に集中するため、手順を簡略化しています。

このレッスンでは、次のことを行います。

- GitHub Issue から Copilot の新しい会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新しい機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動で検証します。

機能開発を続ける中で、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、Model Context Protocol (MCP) による検証を追加して、品質保証 (QA) エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、訪問者はカテゴリやパブリッシャーでゲームを絞り込む必要があります。バックログの Issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意しておくべき詳細があります。Plan モードで要件を決めてから、Autopilot に範囲を定めた実装を許可します。

## 背景

AI コーディング エージェントを開発フローに取り入れても、基本的な作業は変わりません。むしろ、より重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業を記載した Issue から始めます。
2. 構築するものの計画を立てます。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードのレビューと継続的インテグレーションが成功したら、マージします。

> [!NOTE]
> 詳細な手順はチームや組織によって異なりますが、多くの場合は上記の流れに近いものです。

この標準的な方法を守ることで、AI が生成したコードも要件を満たし、手作業で書いたコードと同じレビュー プロセスを通せます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: 開発者とエージェントが一緒に作業します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントが先に計画を作成し、プロジェクト ファイルを編集できない状態になります。
- **Autopilot**: エージェントがコードを書き、テストを実行し、タスクが完了するまで自律的に改善します。

まず Plan モードで計画を確認し、次に Autopilot で実装します。

## Issue から始める

フィルター機能の作業を始める前に、codespace に戻り、リポジトリとターミナルを準備します。

1. codespace に戻ります。停止している場合は、再起動してから続行します。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新してから、フィルター機能用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての Issue を表示します。
8. 矢印キーを使って、**Allow users to filter games by category and publisher** というタイトルの Issue を選択します。
9. <kbd>C</kbd> を押して Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または同様の番号) で始まることを確認します。`#` を使うと、GitHub 上の Issue やプルリクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てることで、機能の実装やタスクの実行方法を Copilot に依頼する前に決められます。複雑な作業では、事前に時間をかけて計画することをお勧めします。Plan モードに切り替えて、Copilot に計画を作ってもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** であることを確認します。
2. 前の手順で追加した Issue の後に、次のプロンプトを入力します。

   ```plaintext
   この機能を実装するための計画を作成してください。
   ```

Copilot はプロジェクトを調べ、適切な方法を検討して計画を作成します。

3. フィルターの動作について質問された場合は、希望に基づいて回答します。正解は 1 つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画を上下にスクロールして確認します。
6. 決めた内容と異なる部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Autopilot を使うと、Copilot は完了したと判断するまで問題に取り組み、反復して改善します。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みバージョンで同様のラベルの選択肢を選択します。
2. プロンプトの下のモード表示が **Autopilot** であることを確認します。
3. Copilot が計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、すぐに実装が始まる場合があります。先に計画を確認してください。Copilot が依存関係の不足やポートの競合を報告した場合は、チェック完了と判断する前にセットアップの問題を解決します。

## 実装をレビューして検証する

生成されたコードは、ほかのコードと同じようにマージ前にレビューします。コードを確認し、サイトを実行して問題がないか調べましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルターの実装とテストを確認します。
3. 結果を Issue と計画で決めた内容に照らし合わせます。
4. コードをレビューしたら、<kbd>Esc</kbd> を押して差分画面を閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新しい機能を試す

コードは問題なさそうですが、実際に動くでしょうか。アプリを起動し、Codespaces の転送ポートでサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   ブラウザーでフィルター機能を試せるように、アプリを起動してください。URL を教えて、サーバーは実行したままにしてください。
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. カテゴリ、パブリッシャー、および計画で合意した組み合わせでフィルターを試します。
4. リセットと結果が空の場合の動作が、Issue と決定内容に合っていることを確認します。
5. codespace に戻り、Copilot に開発サーバーを停止するよう依頼します。

## まとめと次のステップ

さまざまな会話モードを使って、機能を構築しレビューしました。このレッスンでは、次のことを行いました。

- GitHub Issue から Copilot の新しい会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで新しい機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動で検証しました。
