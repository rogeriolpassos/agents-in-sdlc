アプリケーションの簡単な更新でも、通常は複数のファイルを変更し、テストなどを実行する必要があります。開発者は必要なファイルを探し、変更を行い、テストを実行して、デバッグし、更新し忘れたファイルを見つけ、さらに修正する、といった作業を行います。

ここで役立つのが Copilot エージェント モードです。

エージェント モードは統合開発環境 (IDE) 内でより自律的に作業するよう設計されています。既存のプロジェクト構成を調べ、必要な変更を行い、テストなどのタスクを実行し、見つかった問題を自動的に修正します。エージェント モードを使って Web サイトに機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、エージェント モードと cloud agent は異なる用途向けです。エージェント モードは IDE 内で作業し、素早くやり取りしながら進めます。cloud agent はチーム メンバーのように非同期で作業し、Issue やプルリクエストを通じて連携します。

この演習では、次のことを学びます。

- Copilot エージェント モードでプロジェクトを調べ、関連ファイルを特定し、複数ファイルにまたがる変更を行う方法
- Copilot エージェント モードでユーザー インターフェイス (UI) とデータ層にまたがる新機能を実装する方法
- コードベースにマージする前に、Copilot が生成した変更とテストをレビューする方法

## シナリオ

ゲームの一覧が増えてきたため、カテゴリやパブリッシャーで絞り込めるようにします。前の演習では publishers ヘルパーを追加しました。残りのデータ層、ユーザー インターフェイス (UI)、テストの作業を Copilot エージェント モードで完了します。

## Tailspin Toys Web サイトを実行する

変更を加える前に、現在の機能を理解するため、Tailspin Toys Web サイトを確認します。

この Web サイトは、開発者をテーマにしたボードゲームのクラウドファンディング サービスです。ゲームの一覧と詳細を表示できます。単一の Astro アプリであり、ビルド時に HyperText Markup Language (HTML) としてページを静的にレンダリングします。ページは frontmatter で Drizzle ORM を通じてローカル SQLite データベースを直接参照します。独立したバックエンド アプリケーション プログラミング インターフェイス (API) やクライアント側ユーザー インターフェイス (UI) フレームワークはありません。再利用可能なデータ アクセス ヘルパーは `src/lib/` にあり、標準のドキュメント オブジェクト モデル (DOM) API を使う小さなスコープ付き Astro `<script>` で操作性を追加します。

### Web サイトを起動する

Web サイトを簡単に実行できるように、単一の Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。GitHub Codespace で次の手順を実行します。

1. codespace に戻ります。前の演習を終えて `main` に戻っているはずです。
2. <kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押して、Codespace 内に新しいターミナルを開きます。
3. `main` を更新し、フィルター機能用のブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーが起動すると、次のような URL を含むメッセージが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くよう促すダイアログが表示された場合は、**x** を選択して閉じます。

5. <kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押しながら、ターミナルに表示された Astro サーバーのアドレス `http://localhost:4321` を選択して Web サイトを開きます。

> [!NOTE]
> codespace では、Codespace のターミナルにある localhost URL を選択すると、`https://<your-codespace-name>-4321.app.github.dev/` にリダイレクトされます。これは、Web サーバーをホストしている codespace へのプライベート トンネルです。

### Web サイトを確認する

Web サイトを起動したら、現在の機能を確認します。主な機能は次のとおりです。

- **Home Page**: ボードゲームのタイトル、画像、説明を一覧表示します。
- **Game Details Page**: ゲームを選択すると詳細ページが開き、タイトル、説明、パブリッシャー、カテゴリなどが表示されます。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 以下の演習を始める前に、codespace に戻って Copilot Chat パネルを開き、**New Chat** を選択して新しい会話を始めます。モードとモデルの選択は演習によって異なるため、必要な箇所で説明します。

Web サイトの初期実装は動作しますが、新しい機能を追加して改善します。まずバックログを確認します。テンプレートからプロジェクトを作成したとき、Issue のバックログも自動作成されています。GitHub Copilot に項目を表示してもらいましょう。

1. Chat ビューのエージェント選択メニューから **Agent** を選択します。**Agent** は複数ファイルの変更を自律的に計画して実装し、ターミナル コマンドを実行してツールを呼び出します。

   ![Chat ビューのエージェント選択メニュー](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデルの一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者が特定のモデルを推奨しているわけではありません。ワークショップの作成時に Claude Sonnet 4.5 を使用したため、手順にも記載しています。提案の一貫性を高め、円滑に進めるためですが、大規模言語モデル (LLM) は確率的に動作するため、提案は異なる場合があります。これは正常な動作です。

> [!NOTE]
> LLM の確率的な性質により、Copilot が別の Model Context Protocol (MCP) コマンドを使うことがありますが、タスクは完了できるはずです。

3. 次のプロンプトを Copilot に送信し、GitHub リポジトリのバックログを確認します。

   ```plaintext
   GitHub リポジトリのバックログを表示してください。ユーザーに最も役立つ項目を基に、優先順位を付けるのを手伝ってください。
   ```

4. **Continue** を選択して、すべての Issue を一覧表示するコマンドを実行します。
5. 生成された Issue の一覧を確認します。

Copilot は、ユーザーに最も役立つと考えた項目に基づいて優先順位も付けています。

## 指示ファイルを確認する

エージェントにコードを生成させる前に、Copilot にコンテキストを与える指示ファイルを確認します。Web サイトへの機能追加方法に関する情報を含む [ユーザー インターフェイス (UI) ファイル](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md)を使います。

1. codespace で `.github/instructions/ui.instructions.md` を開きます。
2. 機能追加のガイダンスを読み、次の内容を確認します。
   - アーキテクチャの概要
   - コンポーネントの設計、テスト容易性、アクセシビリティの原則
   - Astro、Tailwind CSS、Drizzle などのファイルに関する指示へのリンク

> [!TIP]
> 指示ファイルから、ほかの指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルからの相対パスです。指示を再利用し、複雑な内容を管理しやすい小さな単位に分け、例やテンプレートを示せます。

## フィルター機能を実装する

フィルター機能を完成させるには、少なくとも次の 3 つの変更が必要です。

- データ層 (`src/lib/`) の残りのフィルター ロジックを追加または調整します。
- フィルターの動作を確認するテストを追加または更新します。
- ゲーム一覧ページにフィルター UI を追加します。

さらに、コードベースにマージする前にテストが成功する必要があります。Copilot エージェント モードに作業を依頼しましょう。

1. 現在の Copilot 会話を続けるか、**New Chat** を選択して新しい会話を始めます。
2. **Add Context**、**Instructions**、**ui** の順に選択し、指示ファイルを追加します。

   ![UI 指示ファイルを選択する例](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント選択メニューで、引き続き **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント選択メニュー](../../../_images/shared-chat-mode-selector.png)

4. モデルとして引き続き **Claude Sonnet 4.5** が選択されていることを確認します。
5. バックログの関連 Issue に基づいて機能を実装するよう、次のプロンプトを Copilot に送信します。

   ```plaintext
   関連する GitHub Issue の要件に基づき、サイトにパブリッシャーとカテゴリのフィルターを追加してください。前の演習で追加した publishers ヘルパーは維持し、必要に応じて調整しながら、残りのデータ層、UI、テストを完成させてください。完了する前に、すべてのテストが成功することを確認してください。サーバーはすでに起動しているため、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調べ、目的の機能に関連するファイルを探す様子を確認します。データ層のヘルパー、UI、テストを見つけ、ファイルを変更してテストを実行します。

   ![Copilot がプロジェクト ファイルを調べる画面](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの変更、テストの実行などを行います。タスクやコードベースの複雑さによって、数分かかることがあります。作業中、コード エディターに **Keep** と **Undo** が表示される場合があります。作業中に選択する必要はありません。Copilot が完了すると、すべての変更に対して **Keep** または **Undo** が表示されます。

7. Copilot が求めたら **Continue** を選択して、テストを実行します。

   ![Copilot Chat のテスト実行の確認ダイアログ](../../../_images/ex3-agent-mode-run-tests.png)

8. Copilot が作業を進める間、一時停止したりテストが失敗したりすることがあります。問題ありません。Copilot はコード生成とテストを繰り返し、完了してエラーがないと判断するまで作業します。

   ![Copilot エージェント モードの完了した Chat セッション](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot やほかの AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトを開いたブラウザーに戻り、新しい機能を試します。
11. 動作を確認し、コードをレビューしたら、Copilot Chat ウィンドウで **Keep** を選択します。

### ボーナス演習 - ページネーションを実装する

ゲーム一覧が増えると、ページネーションが必要になります。この演習で学んだことを使い、Copilot にページネーションを実装するよう依頼します。コードを作成する際は、次の点を検討してください。

- 既存の指示ファイルを使うなど、既存のベストプラクティスに従います。
- ページサイズをユーザーが選べるようにするか、固定値にするかなど、ページネーションの動作を決めます。
- 希望する実装に必要なガイダンスを Copilot に伝えます。
- 変更を依頼したりコンテキストを追加したりして、Copilot に繰り返し改善を依頼する場合があります。これは Copilot を使う通常の流れです。
