エージェント モードで GitHub Copilot を使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、その作業をリアルタイムで確認できます。すべてのツール呼び出しやファイル編集を確認し、差分を見ながら個別の変更を採用または却下できます。エディターを離れずに追加のプロンプトを送り、作業を調整したり広げたりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントに指示し、ハイコントラスト モードにライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントが、ハイコントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいという要望がありました。新しい会話を始めるのではなく、既存のセッションに指示を追加して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各作業が表示されます。確認したファイル、実行したコマンド、提案した編集などです。ファイル編集は差分と **Keep** / **Undo** の操作を含めてチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行許可を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を元に戻してエージェントに再度試させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ツールの実行許可 (たとえばターミナル コマンドの実行) を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラスト モードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラスト モードができたら、同じ会話にライトモードの切り替えを追加します。同じチャット セッションを続けることで、エージェントは変更したコンポーネント、スタイル、local storage のパターンなど、前の作業のコンテキストを引き継ぎます。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

   ```plaintext
   よくできました。ハイコントラストの切り替えと並べて、ライトモードの切り替えも追加してください。ライトモードも同じパターンに従い、local storage で設定を保持し、同じ UI 領域から選べるようにしてください。ハイコントラストとライトモードは、それぞれ独立して有効にできるようにします。
   ```

2. エージェントが以前の変更を調べ、ライトモードの追加を提案することを確認します。
3. 新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (たとえば、切り替え UI を意図しない方法でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加指示を送ります。

> [!TIP]
> 進行中のセッションに追加の指示を送ると、最初からやり直すより速く調整できます。追加プロンプトで変更を依頼します (例: 「カスケーディング スタイル シート (CSS) を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」)。また、方向を修正します (例: 「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを組み込んでください」)。作業範囲を広げることもできます (例: 「両方の切り替えにキーボード ショートカットも追加してください」)。

## 作業セットをレビューする

コミットする前に、エージェントが変更したファイル全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ パターンである Accessible Rich Internet Applications (ARIA) 属性、キーボード ナビゲーション、セマンティックな HyperText Markup Language (HTML)、local storage による設定保持が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視し、方向付けました。ファイル編集を確認しながら採用または却下し、コンテキストを失わずに追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する方法
- 個々のファイル編集を採用または却下する方法
- 追加プロンプトを使ってセッションの途中で方向を調整する方法
